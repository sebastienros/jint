# AngleSharp divergences found by the DOM bindings

**Data, not instructions.** This is the register [`AGENTS.md`](AGENTS.md) points at: every place AngleSharp
answers differently from the standard that the bindings had to work around, so the next agent recognises one
it has already met and nobody patches around the same thing twice. The rule that governs it — record the
divergence, never work around it silently, never open an issue on AngleSharp without being asked — is in that
file, which is where an agent is told to look before it edits anything here.

Divergences that are **AngleSharp's**, found by this work and to be reported upstream rather than patched
here:

| What | The standard | AngleSharp |
| --- | --- | --- |
| `Range.comparePoint` / `isPointInRange` | DOM §5.5 checks the argument root, uses node length (including CharacterData), and includes both endpoints | `IRange.CompareTo` checks its own start root instead of the argument root and validates against child count. `Contains` also uses child count, excludes endpoints, and compares node length instead of the point offset. `DomRangeMembers` performs the standard checks and delegates tree ordering through `CompareBoundaryTo` on a private collapsed clone; same-container queries need no clone. Tracked in [#3915](https://github.com/sebastienros/jint/issues/3915) |
| `node.isConnected` | DOM §4.4: whether the node's shadow-including root is a document | `INode` has no member for it at all, so nothing is projected — and every client library asks a node handle this before it clicks it, so an absent member makes every element read as detached. Re-declared in `additions` |
| `el.dataset.fooBar` and `delete el.dataset.foo` | HTML §3.2.6 converts between property names and `data-*` attribute names, and the deleter removes the content attribute | `IStringMap` accepts raw attribute suffixes and rejects uppercase ASCII. Its deletion bug is fixed in 1.7.3 ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1310)), but that does not supply WebIDL's name conversion or setter validation: `DomStringMapAdapter` still projects the associated element |
| `el.querySelectorAll(…)` | DOM §4.2.6 returns a static `NodeList` | fixed in 1.8.0: the result implements `INodeList` and `[DomReturnType(typeof(INodeList))]` identifies its IDL projection despite the unchanged CLR signature ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1318)). The generator consumes that metadata, so `DomStaticNodeList` was removed. `INodeList` already had its indexed getter in 1.7.2; the 1.7.3 indexed-getter addition was to `ITextTrackCueList` |
| `NodeList.item(index)` outside the supported indices | DOM §4.2.10.1 returns `null` | the underlying node-list and query-collection indexers can still throw `ArgumentOutOfRangeException` in 1.8.0, which the binding translates to `TypeError`. Indexed property reads are separately bounds-checked and answer `undefined`; that guard does not cover the `item` operation |
| `el.style.color` | CSSOM serializes an opaque colour as `rgb(r, g, b)` | Css 1.1.0 adds `CssColorValue.UseSpecSerialization`, but the default still serializes opaque colours as `rgba(r, g, b, 1)`. Jint does not change this process-global mutable switch on behalf of every AngleSharp consumer |
| `el.children === el.children` | one `HTMLCollection` per element | a fresh collection per call, so the wrapper cache has nothing to key identity on. The 1.8.0 `[DomSameObject]` annotation documents the promise but does not implement it |
| `document.getElementsByClassName('x')` after the tree or class attributes change | a live `HTMLCollection` of descendants matching the class names | a snapshot. The Document and Element hooks re-run AngleSharp's class matching through `DomLiveHtmlCollection` on each read ([#3897](https://github.com/sebastienros/jint/issues/3897)) |
| `getElementsByClassName('A a')` in quirks mode | [DOM's class-name collection algorithm](https://dom.spec.whatwg.org/#concept-getelementsbyclassname) compares ASCII case-insensitively in quirks mode and identically otherwise; U+212A KELVIN SIGN stays distinct from ASCII K/k | 1.8.0 compares case-sensitively in both modes. With `<html class="a A"><body class="a a">` and no doctype, the document query returns only `html`, omitting `body`. Current upstream [class matching](https://github.com/AngleSharp/AngleSharp/blob/1b8579bea408b816891c61d047eb80152fc4f9af/src/AngleSharp/Dom/QueryExtensions.cs#L371-L385) still uses `ClassList.Contains`; the CSS class-selector path has the same defect and no comparer overload is exposed. The live collection added by [#3900](https://github.com/sebastienros/jint/pull/3900) preserves that query behavior. [#3899's standalone reproduction and API audit](https://github.com/sebastienros/jint/issues/3899#issuecomment-5575991763) record the dependency blocker; its WPT exclusion remains. No upstream issue has been filed |
| `:lang(en)` on an element with no declared or inherited language | [Selectors §8.1](https://drafts.csswg.org/selectors-4/#the-lang-pseudo) matches the element's content language; an element whose language is unknown matches no language range | 1.8.0 falls back to `IBrowsingContext.GetCulture()`, so the element matches on an English-culture context and does not on an invariant one. `ParserDriver` supplies the page engine's `Options.Culture` to make that fallback independent of the parser thread, and the browser WPT lane pins invariant culture, but neither changes AngleSharp's matching rule. An upstream report has been drafted but not filed |
| `a:enabled`, `area:enabled` and `link:enabled` | [Selectors §13.1](https://drafts.csswg.org/selectors-4/#enableddisabled) limits `:enabled` to user-interface elements which have a corresponding disabled state; HTML links have none | Css 1.1.0 matches every `IHtmlAnchorElement`, `IHtmlAreaElement` and `IHtmlLinkElement`, with or without `href`. `PagePseudoClassSelectorFactory` refuses those three HTML interfaces before delegating every other element to AngleSharp's selector, preserving its form-control behavior. No upstream issue has been filed |
| `:target` with duplicate IDs, a matching shadow-tree ID, or a disconnected element | [Selectors §8.2](https://drafts.csswg.org/selectors-4/#the-target-pseudo) matches the document's target element; HTML selects the first matching ID or legacy named anchor in the document tree, trying the raw fragment before its percent-decoded form | 1.8.0's `IsTarget` compares each candidate's ID with its owner document's location, so every duplicate, a shadow descendant, and a disconnected clone can match. `PagePseudoClassSelectorFactory` selects the one indicated element from the HTML document instead. No upstream issue has been filed |
| `document.getElementsByTagName('x')` after the tree changes | a live `HTMLCollection`, with qualified-name matching that folds ASCII only for HTML-namespace elements in an HTML document | a snapshot, and its one comparison folds names from other namespaces too. `DomLiveHtmlCollection` re-runs the filter for every read; the four Document/Element qualified-name and namespace-name operations reach it through generated hooks |
| `getElementsByTagNameNS('test', 'BODY')` | DOM's namespace/local-name collection algorithm matches both strings exactly and returns a live `HTMLCollection` | the exact-namespace query folds the requested local name, although `IElement.LocalName` retains the created case. The generated hook traverses non-HTML namespaces itself; exact HTML-namespace queries stay on AngleSharp's path because that path retains name information its `IElement` surface does not expose ([#3948](https://github.com/sebastienros/jint/issues/3948)) |
| `link.href` after the document's first `<base href>` is removed | HTML's URL-reflection algorithm resolves the content attribute against the element's node document's current base URL on every read | `IHtmlLinkElement.Href` retains the removed base element's URL. The reflected-attribute descriptor now reads `PageRuntime.BaseUri` for the page's own document and derives the current first `base[href]` against the owner document's uncached URL everywhere else ([#3896](https://github.com/sebastienros/jint/issues/3896)) |
| `meta.charset` | HTML declares a `charset` content attribute but no corresponding IDL member | 1.7.3 annotates its CLR convenience property with `[DomName("charset")]`; the override table omits it while preserving normal content-attribute access |
| invalid selector failures | a catchable `SyntaxError` DOMException | the old `:has(*,:jqfake)` null dereference is fixed upstream, so the selector-only wrapper and its broad `NullReferenceException` translation were removed. Generated selectors use `DomFailures.Guard` like other DOM operations; remaining selector-matching differences stay upstream |
| an invalid selector on an empty `DocumentFragment` | selectors are parsed before matching, so `querySelector('[')` and `querySelectorAll('[')` raise `SyntaxError` even when nothing can match | 1.8.0 returns an empty result without parsing. This also occurred through the removed selector wrapper; error translation cannot supply validation the underlying call never performs |
| `el.id` when the attribute is absent | `""` | fixed in 1.7.3 along with other attribute-backed getters ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1313)). `DomConvert.Text` remains the non-nullable `DOMString` conversion, not a workaround specific to `id`; nullable DOM returns still take `NullableText` |
| `insertAdjacentHTML`'s position | a WebIDL enumeration | 1.7.3 adds `[DomLiterals]` to `AdjacentPosition` ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1311)). Its generated conversion is unchanged; the general lower-case-field heuristic still serves other enums without that attribute |
| `matchMedia(q).matches` | evaluates the query against the viewport and media preferences | Css 1.1.0 replaces the native stub and fixes list OR, media-type guards, orientation/scan constants and scripting. `PageRenderDevice.IRenderDevicePreferences` now lets native stylesheet rules read the page's defaults and emulated preferences. `Runtime/MediaQuery` remains: the release still distributes `not` across conjunction terms, mishandles boolean dimensions and colour availability, throws on malformed query text, and lacks ordered gamut/dynamic-range validators. The page also owns preference-change notification and scheduling |
| `document.currentScript` | HTML §4.12.1: the classic script whose text is running | 1.7.3 fixes AngleSharp's own execution path ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1308)). The getter hook remains because Jint's parser driver also schedules and executes scripts itself; the page's `CurrentScript` brackets that execution and restores the previous script. Bindings without a page runtime delegate to AngleSharp |
| `document.readyState` | HTML §3.1.6: the host advances it and fires `readystatechange` | `Document.ReadyState`'s setter is `protected`, so nothing outside AngleSharp can move it; the parser driver's readiness is answered by a getter hook over `PageRuntime.ReadyState` |
| `<script async src>` | HTML: it executes the moment its fetch lands, in no particular order | `HtmlScriptElement.InvokeLoadingScript` puts `defer` and `async` into the one `_loadingScripts` queue, so an async script executes in document order at the end of the parse |
| `document.write` after the parse | HTML: it implies `document.open()`, which replaces the document | `Document.Open` blocks on `PromptToUnloadAsync().Result` and `Unload(recycle: true).Wait()` — synchronous waits on asynchronous work, inside a DOM member a script calls. `DomHostHooks.Write` refuses instead |
| a custom `IResourceLoader` | a host wants scripts and style sheets and not images | every request processor asks the same `IResourceLoader`, and only `WithDefaultLoader`'s `LoaderOptions` can filter by kind — so a host supplying its own loader has to refuse per element type itself |
| `location.host = …` (and `pathname`, `port`, `protocol`, `search`) | a navigation the page can observe | raises `Location.Changed`, which `Document.LocationChanged` handles in a fire-and-forget `async void` calling `IBrowsingContext.OpenAsync` — on whatever thread the setter ran on. **Unreachable from script**, because `Runtime/LocationInstaller` shadows every `Location` member with an own property over the page's own URL; AngleSharp's location is never written |
| `el.classList.add('x')` | DOM §7.1's token list writes the content attribute, which is an attribute change | `TokenList` writes it through its own `Changed` event, which raises neither `IAttributeObserver.NotifyChange` nor a mutation record, so an observed `class` attribute reported no `attributeChangedCallback`. **No longer reachable**: §7.1's update steps are `DomTokenListMembers`' and are a plain *set an attribute value* — the same door `setAttribute` comes through — so the notification arrives. The row stays because the AngleSharp behaviour is unchanged and any other caller of `ITokenList` still meets it |
| `el.setAttributeNS(ns, 'x', 'v')` | an attribute change like any other | `IAttributeObserver` is not called for a namespaced write, so only a *connected* element's change is seen — through the mutation record instead |
| `attr.value = 'v'` on an `Attr` node | DOM §4.9.2: setting an attribute's value is a change of that attribute | neither channel is raised, so nothing observes it |
| `<dl>`, `<dt>` and `<dd>` | HTML gives `<dl>` an `HTMLDListElement`, whose one member is the obsolete `compact`, and `<dt>`/`<dd>` a plain `HTMLElement` | there is no `IHtmlDListElement` and no `[DomName("HTMLDListElement")]` at all, so a `<dl>` is an `HTMLElement` and there is no interface for a `reflected` row to put `compact` on; `<dt>` and `<dd>` are `IHtmlListItemElement`, so they carry `HTMLLIElement`'s `value` and `type` |
| `&lt;th&gt;` and `&lt;td&gt;` | HTML gives both `HTMLTableCellElement` | `IHtmlTableHeaderCellElement` and `IHtmlTableDataCellElement`, two `[DomName]` interfaces HTML does not have, which is why the `HTMLElement` constructor's interface check accepts an ancestor — `CustomElements/CustomElementRegistry.Construction.cs` states what that relaxation costs |
| `observer.disconnect()` | DOM §4.3.3 empties the observer's registered-node list | `MutationObserver.Disconnect` unregisters it from the document but leaves that list populated, so the **next** `observe()` of any node silently re-registers every node it used to watch |
| `observer.observe(document, …)` | observes the document node | `Connect` silently retargets a `Document` to its `documentElement`, so a `childList` mutation of the document itself is never reported. With `subtree: true` — how nearly every page writes it — nothing else changes |
| `observe(…)` with bad options | a `TypeError` | a `DomException` (`TypeMismatchError` / `SyntaxError`), and its resolution of the dictionary's optional members differs from the standard's: `{ attributeOldValue: false }` alone is valid in DOM and invalid there |
| `record.addedNodes` on an attribute record | an empty `NodeList` | `null`, for both `Added` and `Removed` |
| `IShadowRoot.Mode` | `ShadowRoot.mode` | fixed in 1.7.3 by adding `[DomName("mode")]` ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1301)). The local `additions` entry was removed; the generated accessor now comes from the upstream metadata |
| `slot.assignedNodes()` | DOM §4.2.5 | named `getDistributedNodes`, the Shadow DOM v0 spelling |
| `getComputedStyle(span).display` | `inline` | the empty string: the cascade reports only what a stylesheet *declared*, and `display: inline` is CSS's initial value, so the user-agent sheet does not declare it. A declared one (`div` → `block`) resolves. `Dom/Views/ResolvedStyle` answers the initial value over it for this and nine other properties, which is the whole of the exception — see [`../AGENTS.md`](../AGENTS.md)'s divergence table |
| the computed style is writable | CSSOM's computed flag makes every write a `NoModificationAllowedError` | an ordinary writable declaration, and a detached one, so a write neither throws nor changes anything readable — see `Dom/Views/ReadOnlyStyleDeclaration` |
| circular CSS custom properties | [CSS Variables §2.3](https://drafts.csswg.org/css-variables-1/#cycles): every member of a dependency cycle, including edges in unused fallbacks, is guaranteed-invalid; consumers may use a fallback | fixed by Css 1.1.0's native computed-style pipeline ([AngleSharp/AngleSharp.Css#242](https://github.com/AngleSharp/AngleSharp.Css/pull/242), following [#3851](https://github.com/sebastienros/jint/issues/3851)). Individual `CssCascade.Of` queries delegate to it. `Dom/Views/CustomProperties` remains for cached tree traversals because the native computed-parent API is internal: the public per-element API rematches ancestors, and the recursive bulk renderer cannot preserve the traversal's style collection and per-element failure isolation. Invalid declared properties now receive native inherited/initial values; the ten-property policy for undeclared values, read-only wrapper and guarded-cascade policy are unchanged |
| explicit `inherit` without a declared value on the parent | CSS Cascade resolves inheritance rather than returning the keyword | the Css 1.1.0 computed-parent path can leave a non-inherited property's value as literal `inherit`. `CssCascade.Of` detects this and retains the pre-upgrade ancestor-walk compatibility path; it is not a reason to bypass native custom-property resolution on ordinary queries |
| `el.click()` on a checkbox, radio, `<summary>` or `<a href>` | the element's activation behaviour runs | `DoClick` dispatches on AngleSharp's own bus and runs **no activation behaviour at all**, with or without a browsing context: nothing toggles, opens or navigates |
| `document.activeElement` | the focused element, or the body | `null` for the life of every document — nothing in AngleSharp ever assigns it, `DoFocus()` included |
| `input.labels` | every `<label>` whose labeled control is the input, in tree order | an empty collection. No longer reached directly: `HtmlLabelAssociation` supplies the live `NodeList` shared by the bindings and accessible-name computation |
| `label.control` | the labeled control: the `for` target, or the first labelable **descendant** | `null` for a control the label contains, which is the commoner spelling. No longer reached directly: `HtmlLabelAssociation` supplies the binding and label activation |
| `select.selectedIndex` with no `selected` option | 0 — the selectedness-setting algorithm picks the first option of a non-`multiple`, display-size-1 select | −1 |
| `select.selectedIndex = index` | [HTML's writable `selectedIndex`](https://html.spec.whatwg.org/multipage/form-elements.html#dom-select-selectedindex) selects the indexed option and clears the others, including for a multiple select; an invalid index clears all | `IHtmlSelectElement.SelectedIndex` has no setter, although `IHtmlOptionsCollection.SelectedIndex` does. Re-declared in `additions` using that setter, preserving the same live option state, selected attributes and form-reset path. AngleSharp's existing option dirtiness and automatic default-selection limitations are unchanged |
| `input.value = …` | the cursor moves to the end and the selection is dropped | `SelectionStart`/`SelectionEnd` are left where they were, so they can point past the end of the new value |
| `input.setSelectionRange` on a `type=checkbox` | `InvalidStateError` — the type does not support selection | answers, so the type test has to be the caller's |
| `DomException.Name` | DOM's error name — `HierarchyRequestError` | the **enum field name**, `HierarchyRequest`, so the string can never be handed to a page; `DomFailures.NameOf` is the table that maps a `DomError` to the standard's name, and `DomExceptionTests` pins every row of it |
| `DomError.Validation` | WebIDL's legacy code for `ValidationError` is 16 | 15 — the value of `DomError.InvalidAccess` — so the two are one number and no `ValidationError` can be told from an `InvalidAccessError` |
| a `DomException`'s message | a browser names the operation and what it refused | AngleSharp's own sentence, which is what `DomFailures` puts after the `Failed to execute '<interface>.<member>': ` prefix. DOM specifies a `name` and nothing about wording, and a page branches on the name |
| `insertAdjacentHTML('beforebegin')` on an element with no parent element | HTML step 2: a `NoModificationAllowedError` | the one `DomException` in the assembly built from a *string*, so it carries no `DomError` at all and its `Name` is the sentence "The element has no parent."; `DomHostHooks.InsertAdjacentHtml` makes that refusal itself |
| `createElementNS(null, 'a:b')`, `setAttributeNS(null, 'a:b', …)` | DOM's validate-and-extract is a `NamespaceError` for a prefixed name with no namespace | no refusal at all, so an element or attribute is created with a prefix nothing declares. The `xmlns` half of the same algorithm *is* checked |
| `walker.previousNode()` | DOM §6.1: a walk that ends, because every pass moves the node strictly backward in pre-order or returns | `TreeWalker.ToPrevious` never assigns the `sibling` variable inside the loop that reads it and never climbs to the parent, so it **spins forever** the moment the previous sibling is not accepted outright — a `FILTER_REJECT`, a `FILTER_SKIP`, or a `currentNode` outside the root beside a node `whatToShow` excludes. **The one algorithm this package does not take from AngleSharp**: `Dom/Views/DomTreeWalker` implements all seven traversals, because carrying only the broken method would leave two walks and a termination argument for neither. It is a denial of service rather than a conformance gap — a node `whatToShow` excludes is `FILTER_SKIP` without the page's filter being called, so the loop never re-enters the engine and no constraint, cancellation token or page budget is ever consulted ([#3765](https://github.com/sebastienros/jint/issues/3765)) |
| `el.classList.add('')` / `add('a b')` | DOM §7.1: a `SyntaxError` for the empty token, an `InvalidCharacterError` for one containing ASCII whitespace | neither is validated, so `ITokenList` takes both. **The whole of §7.1's mutating half is `Dom/Collections/DomTokenListMembers` now**, because the validation steps are only the first of five things the interface cannot say: `toggle`'s `force` is a CLR `bool force = false`, which cannot tell "given as false" from "not given"; there is no `replace` and no `supports`; the indexer throws where WebIDL's indexed getter answers `null`; and the *update steps* rewrite the attribute in serialized form even when the token set did not move, where AngleSharp notifies only on a change. What stays AngleSharp's is the token set itself and the attribute it is bound to |
| `iframe.sandbox.supports('allow-scripts')` | HTML defines a supported-token set for `rel` and `sandbox`, so this is `true` | there is no supported-token set anywhere in the assembly, so `supports` answers the `TypeError` DOM prescribes for an attribute that defines none — right for `class`, and a refusal for the two attributes that do define one |
| `iframe.sandbox instanceof DOMTokenList` | DOM merged `DOMSettableTokenList` into `DOMTokenList` in 2016 | `ISettableTokenList` still carries `[DomName("DOMSettableTokenList")]`, so `sandbox`, `htmlFor` and `link.sizes` land on an interface the standard no longer has. Its one member *is* skipped — `Value` answers the serialized token set where DOM's `value` is the attribute verbatim — so the shape is empty and everything is inherited; the name is the whole of what is left |
| `node.replaceWith(…)` | DOM §4.2.7's name | `IChildNode` is `[DomName("replace")]`, a name the standard has not got — skipped and re-declared. The algorithm diverges twice more: it converts its arguments before it checks for a parent, so a parentless child's call still moves them; and it refuses when the child is among its own replacements |
| `el.setAttributeNode(a)` on an observed attribute | the reaction's `newValue` is the attribute's | `null`: an `Attr` write reaches the attribute observer without its value |
| `input.selectionDirection` on a control nothing has selected in | HTML [§4.10.5.4](https://html.spec.whatwg.org/multipage/input.html#dom-textarea-input-selectiondirection): `none`, and `setSelectionRange(start, end)` with no third argument sets `none` | `forward` in both cases, so a page cannot tell a selection a user dragged left-to-right from one that has no direction at all. `Events/TextEditing` compares which end the caret is at rather than the string, which is its own model of direction anyway; without that, the first caret key in every control would look like a change of direction and fire a `selectionchange` |
| `el.classList.add('x')` | DOM §7.1's token list writes the content attribute, which is an attribute change | neither `IAttributeObserver.NotifyChange` nor a mutation record is raised, so an observed `class` attribute reports no `attributeChangedCallback` |
| `document.createCDATASection(d)` | DOM §4.5: on `Document` unconditionally, and a `NotSupportedError` on an HTML document | `IDocument` has no member for it — a CDATA section is `AngleSharp.Xml`'s `IXmlCDataSection`, and that assembly is not in the generator's pin. Re-declared in `additions`, refusing HTML documents itself and reaching `IXmlDocument.CreateCDataSection` for the rest. **A missing member is the wrong refusal**, not merely a missing one: a page guarding with `try`/`catch` catches the standard's `NotSupportedError` where a `TypeError` for an absent member reaches it before the guard means anything, which is why one member was worth thirty-one wpt documents |
| `document.implementation.createDocument(…)` | DOM §4.5.1: a new `XMLDocument`, its content type taken from the namespace | `IImplementation` is `createHTMLDocument`, `createDocumentType` and `hasFeature`, and nothing else. Re-declared in `additions` over the pieces AngleSharp does have — the empty XML parse `new Document()` uses, `createElementNS`, and DOM's own append. **Two steps it cannot take**: `Document.ContentType`'s setter is not public, so every document it makes answers `application/xml` where the HTML and SVG namespaces call for `application/xhtml+xml` and `image/svg+xml`; and the result is wrapped as `Document`, because `XMLDocument` is a name no pinned assembly the generator reads declares |

| `createElement('f<oo')`, `createAttribute('1foo')` | DOM §1.4's predicates allow every name the HTML parser can build — the XML `Name` production was deliberately dropped | `String.IsXmlName` is still that production, so a name a browser accepts is refused. **Unreachable from this side**: an element's local name is fixed by AngleSharp's own factories, which are internal to that assembly, so nothing here can build the element the standard asks for. | a `NodeIterator` whose filter removes a node | DOM §6.1 moves a *candidate* reference, promotes it only on `FILTER_ACCEPT`, and its pre-remove steps adjust **both** positions | `NodeIterator.Next` keeps the in-flight position in a local, so the pre-remove adjustment of the field is overwritten on the way out and the iterator is left on the detached node, from which nothing traverses. `Dom/Views/DomNodeIterator` is DOM's own traversal over **two** of AngleSharp's iterators, each used as the one thing it is reliably — an adjusted node pointer — with the page's filter run outside the AngleSharp call |
| `frame.contentWindow.DOMException === DOMException` | a browser gives every nested browsing context its own realm, so a frame's constructors are its own and this is `false` | `true`. A frame has a **window** of its own here and shares the page's **realm**: `Runtime/FrameWindows` builds an object whose `[[Prototype]]` is the page's global, so every interface object, constructor and intrinsic is inherited. It is not a lie about what the frame throws — a call on the frame's document really does throw the page's `DOMException`, because the page's realm is what built the document's wrapper — but it is a difference a page can see. `frame.contentWindow !== window` and `frames[0] === frame.contentWindow` do hold, which is what the corpus tests. One realm per frame is [#3771](https://github.com/sebastienros/jint/issues/3771)'s remaining half and the survey on that issue says what it would cost |
| `frame.contentWindow.location.href = '…'` | HTML's `Location` setters navigate the browsing context they belong to | a `TypeError` naming the refusal. A frame here has a document rather than a context to navigate, so the three answers were to move the page (the wrong document), do nothing, or refuse — and **doing nothing is the one that must not be chosen**: against a silent no-op `event-global-is-still-set-when-coercing-beforeunload-result.html` waits forever for the frame's `load` and the whole file times out, where a refusal fails it fast. Reads answer the frame's own URL and not the page's, which is why `location` is shadowed rather than inherited; `assign`, `replace` and `reload` are absent, which is loud the same way |
| a frame served `application/xhtml+xml` | HTML [reads it with the XML parser](https://html.spec.whatwg.org/multipage/document-lifecycle.html#read-xml), as it does every XML MIME type | the default content-type mapping sends it to the **HTML** parser, so `<foo>x</foo>` comes back as an HTML document with the text inside an `<html><body>` skeleton. `text/xml` and `application/xml` are right once `WithXml()` is registered; `image/svg+xml` produces no document at all. **Unreachable from this side**, and measured rather than assumed: `DefaultDocumentFactory.Register`/`Unregister` are public, but the configuration *adds* services rather than replacing them, so a second `IDocumentFactory` breaks AngleSharp's own `Single()` resolution for every page — and removing the first (`Without<IDocumentFactory>()`) discards whatever `WithXml()` contributed, which regresses `text/xml` and `application/xml` to HTML. AngleSharp.Xml's XML creator is not public, so nothing can be composed in its place without this package building documents itself. The same package answers the type correctly through `DOMParser` (`Dom/Views/JsDomParser`), which routes all four XML types to `XmlParser` — so a frame and `parseFromString` disagree about the same bytes. `NeedsXmlDocuments` in the browser lane, and 195 rows of `Document-createElementNS.html` plus 49 of `Document-createElement.html` |
