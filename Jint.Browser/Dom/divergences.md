# AngleSharp divergences found by the DOM bindings

**Data, not instructions.** This is the register [`AGENTS.md`](AGENTS.md) points at: every place AngleSharp
answers differently from the standard that the bindings had to work around, so the next agent recognises one
it has already met and nobody patches around the same thing twice. The rule that governs it — record the
divergence, never work around it silently, never open an issue on AngleSharp without being asked — is in that
file, which is where an agent is told to look before it edits anything here.

Divergences that are **AngleSharp's**, found by this work and to be reported upstream rather than patched
here:

| What | The standard | AngleSharp |
| --- | --- | --- |
| `node.isConnected` | DOM §4.4: whether the node's shadow-including root is a document | `INode` has no member for it at all, so nothing is projected — and every client library asks a node handle this before it clicks it, so an absent member makes every element read as detached. Re-declared in `additions` |
| `delete el.dataset.foo` | DOM §3.5's deleter removes the content attribute | `IStringMap.Remove` sets its value to `null` and leaves `data-foo` in place |
| `el.querySelectorAll(…)` | DOM §4.2.6 returns a static `NodeList` | returns an `IHtmlCollection<IElement>`, so `Object.prototype.toString` reports `[object HTMLCollection]` |
| `el.style.color` | CSSOM serializes an opaque colour as `rgb(r, g, b)` | serializes every colour as `rgba(r, g, b, 1)` |
| `el.children === el.children` | one `HTMLCollection` per element | a fresh collection per call, so the wrapper cache has nothing to key identity on |
| `el.id` when the attribute is absent | `""` | `null`, which is why the conversion table's default is the empty string |
| `insertAdjacentHTML`'s position | a WebIDL enumeration | `AdjacentPosition` carries no `[DomLiterals]`; the lower-case-field heuristic is what catches it |
| `matchMedia(q).matches` | evaluates the query against the viewport | `CssMediaQueryList.ComputeMatched` is `return false`, so **every** query answers `false` — a page asking whether it is on a narrow screen is always told no. `Runtime/MediaQuery` answers the subset a page branches on instead |
| `document.currentScript` | HTML §4.12.1: the script whose text is running | the head of the *deferred* script queue, so it is `null` for exactly the case a page uses it in. Answered by a getter hook instead |
| `document.readyState` | HTML §3.1.6: the host advances it and fires `readystatechange` | `Document.ReadyState`'s setter is `protected`, so nothing outside AngleSharp can move it; the parser driver's readiness is answered by a getter hook over `PageRuntime.ReadyState` |
| `<script async src>` | HTML: it executes the moment its fetch lands, in no particular order | `HtmlScriptElement.InvokeLoadingScript` puts `defer` and `async` into the one `_loadingScripts` queue, so an async script executes in document order at the end of the parse |
| `document.write` after the parse | HTML: it implies `document.open()`, which replaces the document | `Document.Open` blocks on `PromptToUnloadAsync().Result` and `Unload(recycle: true).Wait()` — synchronous waits on asynchronous work, inside a DOM member a script calls. `DomHostHooks.Write` refuses instead |
| a custom `IResourceLoader` | a host wants scripts and style sheets and not images | every request processor asks the same `IResourceLoader`, and only `WithDefaultLoader`'s `LoaderOptions` can filter by kind — so a host supplying its own loader has to refuse per element type itself |
| `location.host = …` (and `pathname`, `port`, `protocol`, `search`) | a navigation the page can observe | raises `Location.Changed`, which `Document.LocationChanged` handles in a fire-and-forget `async void` calling `IBrowsingContext.OpenAsync` — on whatever thread the setter ran on. **Unreachable from script**, because `Runtime/LocationInstaller` shadows every `Location` member with an own property over the page's own URL; AngleSharp's location is never written |
| `el.classList.add('x')` | DOM §7.1's token list writes the content attribute, which is an attribute change | `TokenList` writes it through its own `Changed` event, which raises neither `IAttributeObserver.NotifyChange` nor a mutation record, so an observed `class` attribute reported no `attributeChangedCallback`. **No longer reachable**: §7.1's update steps are `DomTokenListMembers`' and are a plain *set an attribute value* — the same door `setAttribute` comes through — so the notification arrives. The row stays because the AngleSharp behaviour is unchanged and any other caller of `ITokenList` still meets it |
| `el.setAttributeNS(ns, 'x', 'v')` | an attribute change like any other | `IAttributeObserver` is not called for a namespaced write, so only a *connected* element's change is seen — through the mutation record instead |
| `attr.value = 'v'` on an `Attr` node | DOM §4.9.2: setting an attribute's value is a change of that attribute | neither channel is raised, so nothing observes it |
| `&lt;th&gt;` and `&lt;td&gt;` | HTML gives both `HTMLTableCellElement` | `IHtmlTableHeaderCellElement` and `IHtmlTableDataCellElement`, two `[DomName]` interfaces HTML does not have, which is why the `HTMLElement` constructor's interface check accepts an ancestor — `CustomElements/CustomElementRegistry.Construction.cs` states what that relaxation costs |
| `observer.disconnect()` | DOM §4.3.3 empties the observer's registered-node list | `MutationObserver.Disconnect` unregisters it from the document but leaves that list populated, so the **next** `observe()` of any node silently re-registers every node it used to watch |
| `observer.observe(document, …)` | observes the document node | `Connect` silently retargets a `Document` to its `documentElement`, so a `childList` mutation of the document itself is never reported. With `subtree: true` — how nearly every page writes it — nothing else changes |
| `observe(…)` with bad options | a `TypeError` | a `DomException` (`TypeMismatchError` / `SyntaxError`), and its resolution of the dictionary's optional members differs from the standard's: `{ attributeOldValue: false }` alone is valid in DOM and invalid there |
| `record.addedNodes` on an attribute record | an empty `NodeList` | `null`, for both `Added` and `Removed` |
| `IShadowRoot.Mode` | `ShadowRoot.mode` | the one member of the interface with no `[DomName]`, so nothing says it is projected |
| `slot.assignedNodes()` | DOM §4.2.5 | named `getDistributedNodes`, the Shadow DOM v0 spelling |
| `getComputedStyle(span).display` | `inline` | the empty string: the cascade reports only what a stylesheet *declared*, and `display: inline` is CSS's initial value, so the user-agent sheet does not declare it. A declared one (`div` → `block`) resolves. `Dom/Views/ResolvedStyle` answers the initial value over it for this and nine other properties, which is the whole of the exception — see [`../AGENTS.md`](../AGENTS.md)'s divergence table |
| the computed style is writable | CSSOM's computed flag makes every write a `NoModificationAllowedError` | an ordinary writable declaration, and a detached one, so a write neither throws nor changes anything readable — see `Dom/Views/ReadOnlyStyleDeclaration` |
| `el.click()` on a checkbox, radio, `<summary>` or `<a href>` | the element's activation behaviour runs | `DoClick` dispatches on AngleSharp's own bus and runs **no activation behaviour at all**, with or without a browsing context: nothing toggles, opens or navigates |
| `document.activeElement` | the focused element, or the body | `null` for the life of every document — nothing in AngleSharp ever assigns it, `DoFocus()` included |
| `input.labels` | the `<label>`s whose `for` names the control | an empty collection |
| `label.control` | the labeled control: the `for` target, or the first labelable **descendant** | `null` for a control the label contains, which is the commoner spelling; `Events/ActivationBehaviors` computes it instead so a click inside a wrapping label reaches its checkbox |
| `select.selectedIndex` with no `selected` option | 0 — the selectedness-setting algorithm picks the first option of a non-`multiple`, display-size-1 select | −1 |
| `input.value = …` | the cursor moves to the end and the selection is dropped | `SelectionStart`/`SelectionEnd` are left where they were, so they can point past the end of the new value |
| `input.setSelectionRange` on a `type=checkbox` | `InvalidStateError` — the type does not support selection | answers, so the type test has to be the caller's |
| `DomException.Name` | DOM's error name — `HierarchyRequestError` | the **enum field name**, `HierarchyRequest`, so the string can never be handed to a page; `DomFailures.NameOf` is the table that maps a `DomError` to the standard's name, and `DomExceptionTests` pins every row of it |
| `DomError.Validation` | WebIDL's legacy code for `ValidationError` is 16 | 15 — the value of `DomError.InvalidAccess` — so the two are one number and no `ValidationError` can be told from an `InvalidAccessError` |
| a `DomException`'s message | a browser names the operation and what it refused | AngleSharp's own sentence, which is what `DomFailures` puts after the `Failed to execute '<interface>.<member>': ` prefix. DOM specifies a `name` and nothing about wording, and a page branches on the name |
| `insertAdjacentHTML('beforebegin')` on an element with no parent element | HTML step 2: a `NoModificationAllowedError` | the one `DomException` in the assembly built from a *string*, so it carries no `DomError` at all and its `Name` is the sentence "The element has no parent."; `DomHostHooks.InsertAdjacentHtml` makes that refusal itself |
| `createElementNS(null, 'a:b')`, `setAttributeNS(null, 'a:b', …)` | DOM's validate-and-extract is a `NamespaceError` for a prefixed name with no namespace | no refusal at all, so an element or attribute is created with a prefix nothing declares. The `xmlns` half of the same algorithm *is* checked |
| `walker.previousNode()` | DOM §6.1: a walk that ends, because every pass moves the node strictly backward in pre-order or returns | `TreeWalker.ToPrevious` never assigns the `sibling` variable inside the loop that reads it and never climbs to the parent, so it **spins forever** the moment the previous sibling is not accepted outright — a `FILTER_REJECT`, a `FILTER_SKIP`, or a `currentNode` outside the root beside a node `whatToShow` excludes. **The one algorithm this package does not take from AngleSharp**: `Dom/Views/DomTreeWalker` implements all seven traversals, because carrying only the broken method would leave two walks and a termination argument for neither. It is a denial of service rather than a conformance gap — a node `whatToShow` excludes is `FILTER_SKIP` without the page's filter being called, so the loop never re-enters the engine and no constraint, cancellation token or page budget is ever consulted ([#3765](https://github.com/sebastienros/jint/issues/3765)) |
| `el.classList.add('')` / `add('a b')` | DOM §7.1: a `SyntaxError` for the empty token, an `InvalidCharacterError` for one containing ASCII whitespace | neither is validated, so `ITokenList` takes both. **The whole of §7.1's mutating half is `Dom/Collections/DomTokenListMembers` now**, because the validation steps are only the first of five things the interface cannot say: `toggle`'s `force` is a CLR `bool force = false`, which cannot tell "given as false" from "not given"; there is no `replace` and no `supports`; the indexer throws where WebIDL's indexed getter answers `null`; and the *update steps* rewrite the attribute in serialized form even when the token set did not move, where AngleSharp notifies only on a change. What stays AngleSharp's is the token set itself and the attribute it is bound to |
| `iframe.sandbox.supports('allow-scripts')` | HTML defines a supported-token set for `rel` and `sandbox`, so this is `true` | there is no supported-token set anywhere in the assembly, so `supports` answers the `TypeError` DOM prescribes for an attribute that defines none — right for `class`, and a refusal for the two attributes that do define one |
| `iframe.sandbox instanceof DOMTokenList` | DOM merged `DOMSettableTokenList` into `DOMTokenList` in 2016 | `ISettableTokenList` still carries `[DomName("DOMSettableTokenList")]`, so `sandbox`, `htmlFor` and `link.sizes` land on an interface the standard no longer has. Its one member *is* skipped — `Value` answers the serialized token set where DOM's `value` is the attribute verbatim — so the shape is empty and everything is inherited; the name is the whole of what is left |
| `node.replaceWith(…)` | DOM §4.2.7's name | `IChildNode` is `[DomName("replace")]`, a name the standard has not got — skipped and re-declared. The algorithm diverges twice more: it converts its arguments before it checks for a parent, so a parentless child's call still moves them; and it refuses when the child is among its own replacements |
| `parent.replaceChildren(…)` | DOM §4.2.6 | absent, and **deliberately so**: replace-all is one mutation record, `ReplaceChild` with a fragment records the removal and no addition, and `ParentNode-replaceChildren.html` waits for that record — so the member turns a document that reports into one that times out |
| `el.setAttributeNode(a)` on an observed attribute | the reaction's `newValue` is the attribute's | `null`: an `Attr` write reaches the attribute observer without its value |
| `doc instanceof XMLDocument` | DOM §4.5 gives an XML document its own interface | one `XmlDocument` serves an XML parse *and* `new Document()`, which DOM makes a plain `Document`, so the CLR type cannot decide it: `HTMLFrameSetElement`'s shape with no local name to select on |
| `input.selectionDirection` on a control nothing has selected in | HTML [§4.10.5.4](https://html.spec.whatwg.org/multipage/input.html#dom-textarea-input-selectiondirection): `none`, and `setSelectionRange(start, end)` with no third argument sets `none` | `forward` in both cases, so a page cannot tell a selection a user dragged left-to-right from one that has no direction at all. `Events/TextEditing` compares which end the caret is at rather than the string, which is its own model of direction anyway; without that, the first caret key in every control would look like a change of direction and fire a `selectionchange` |
| `el.classList.add('')` / `add('a b')` | DOM §7.1: a `SyntaxError` for the empty token, an `InvalidCharacterError` for one containing ASCII whitespace | neither is validated, so the token list takes both |
| `el.classList.add('')` / `add('a b')` | DOM §7.1: a `SyntaxError` for the empty token, an `InvalidCharacterError` for one containing ASCII whitespace | neither is validated, so `ITokenList` takes both. **§7.1's mutating half is `Dom/Collections/DomTokenListMembers` now**: validation is the first of five things the interface cannot say, with `toggle`'s `bool force = false` (which cannot tell "given as false" from "not given"), no `replace`, no `supports`, an indexer that throws where WebIDL answers `null`, and update steps that rewrite the attribute even when the set did not move. The token set and its attribute stay AngleSharp's |
| `el.classList.add('x')` | DOM §7.1's token list writes the content attribute, which is an attribute change | neither `IAttributeObserver.NotifyChange` nor a mutation record is raised, so an observed `class` attribute reports no `attributeChangedCallback` |
| `document.createCDATASection(d)` | DOM §4.5: on `Document` unconditionally, and a `NotSupportedError` on an HTML document | `IDocument` has no member for it — a CDATA section is `AngleSharp.Xml`'s `IXmlCDataSection`, and that assembly is not in the generator's pin. Re-declared in `additions`, refusing HTML documents itself and reaching `IXmlDocument.CreateCDataSection` for the rest. **A missing member is the wrong refusal**, not merely a missing one: a page guarding with `try`/`catch` catches the standard's `NotSupportedError` where a `TypeError` for an absent member reaches it before the guard means anything, which is why one member was worth thirty-one wpt documents |
| `document.implementation.createDocument(…)` | DOM §4.5.1: a new `XMLDocument`, its content type taken from the namespace | `IImplementation` is `createHTMLDocument`, `createDocumentType` and `hasFeature`, and nothing else. Re-declared in `additions` over the pieces AngleSharp does have — the empty XML parse `new Document()` uses, `createElementNS`, and DOM's own append. **Two steps it cannot take**: `Document.ContentType`'s setter is not public, so every document it makes answers `application/xml` where the HTML and SVG namespaces call for `application/xhtml+xml` and `image/svg+xml`; and the result is wrapped as `Document`, because `XMLDocument` is a name no pinned assembly the generator reads declares |
| `attr`/element name productions | DOM's validate-and-extract: an empty prefix or local part is an `InvalidCharacterError`, and the Name production allows `;`, `}` and a non-character | AngleSharp answers a `NamespaceError` for the first and refuses the second, which `DOMImplementation-createDocument.html` finds eighteen more times now that its table runs |
| `createElement('f<oo')`, `createAttribute('1foo')` | DOM §1.4's predicates allow every name the HTML parser can build — the XML `Name` production was deliberately dropped | `String.IsXmlName` is still that production, so a name a browser accepts is refused. **Unreachable from this side**: an element's local name is fixed by AngleSharp's own factories, which are internal to that assembly, so nothing here can build the element the standard asks for. [#3772](https://github.com/sebastienros/jint/issues/3772) |
| a `NodeIterator` whose filter removes a node | DOM §6.1 moves a *candidate* reference, promotes it only on `FILTER_ACCEPT`, and its pre-remove steps adjust **both** positions | `NodeIterator.Next` keeps the in-flight position in a local, so the pre-remove adjustment of the field is overwritten on the way out and the iterator is left on the detached node, from which nothing traverses. `Dom/Views/DomNodeIterator` is DOM's own traversal over **two** of AngleSharp's iterators, each used as the one thing it is reliably — an adjusted node pointer — with the page's filter run outside the AngleSharp call |
