# AngleSharp divergences found by the DOM bindings

**Data, not instructions.** This is the register [`AGENTS.md`](AGENTS.md) points at: every place AngleSharp
answers differently from the standard that the bindings had to work around, so the next agent recognises one
it has already met and nobody patches around the same thing twice. The rule that governs it — record the
divergence, never work around it silently, never open an issue on AngleSharp without being asked — is in that
file, which is where an agent is told to look before it edits anything here.

Divergences that are **AngleSharp's**, found by this work and to be reported upstream rather than patched
here:

| What | The standard | AngleSharp |
| --- | --- | --- |
| `Range.comparePoint` / `isPointInRange` | DOM §5.5 checks the argument root, uses node length (including CharacterData), and includes both endpoints | `IRange.CompareTo` checks its own start root instead of the argument root and validates against child count. `Contains` also uses child count, excludes endpoints, and compares node length instead of the point offset. `DomRangeMembers` performs the standard checks and delegates tree ordering through `CompareBoundaryTo` on a private collapsed clone; same-container queries need no clone. Tracked in [#3915](https://github.com/sebastienros/jint/issues/3915) |
| `node.isConnected` | DOM §4.4: whether the node's shadow-including root is a document | `INode` has no member for it at all, so nothing is projected — and every client library asks a node handle this before it clicks it, so an absent member makes every element read as detached. Re-declared in `additions` |
| `el.dataset.fooBar` and `delete el.dataset.foo` | HTML §3.2.6 converts between property names and `data-*` attribute names, and the deleter removes the content attribute | `IStringMap` accepts raw attribute suffixes and rejects uppercase ASCII. Its deletion bug is fixed in 1.7.3 ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1310)), but that does not supply WebIDL's name conversion or setter validation: `DomStringMapAdapter` still projects the associated element |
| `el.querySelectorAll(…)` | DOM §4.2.6 returns a static `NodeList` | fixed in 1.8.0: the result implements `INodeList` and `[DomReturnType(typeof(INodeList))]` identifies its IDL projection despite the unchanged CLR signature ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1318)). The generator consumes that metadata, so `DomStaticNodeList` was removed. `INodeList` already had its indexed getter in 1.7.2; the 1.7.3 indexed-getter addition was to `ITextTrackCueList` |
| `NodeList.item(index)` outside the supported indices | DOM §4.2.10.1 returns `null` | the underlying node-list and query-collection indexers still throw `ArgumentOutOfRangeException` in 1.8.0. **No longer reachable through `NodeList.item`**: DOM §4.2.10's indexed getter is `Collections/DomNodeListMembers.Item`, a `skip` plus an `additions` entry that bounds-checks before it indexes, the way `DOMTokenList.item` already did. Every other `item` operation over an AngleSharp indexer -- `CSSRuleList`, `MediaList`, `NamedNodeMap`, `StyleSheetList`, `FileList`, `TouchList`, `DOMStringList` -- still translates the raise to a `TypeError`; no vendored document reaches one, which is why the fix is one member and not a table
| `el.style.color` | CSSOM serializes an opaque colour as `rgb(r, g, b)` | Css 1.1.0 adds `CssColorValue.UseSpecSerialization`, but the default still serializes opaque colours as `rgba(r, g, b, 1)`. Jint does not change this process-global mutable switch on behalf of every AngleSharp consumer |
| `el.children === el.children` | one `HTMLCollection` per element | a fresh collection per call, so the wrapper cache has nothing to key identity on. The 1.8.0 `[DomSameObject]` annotation documents the promise but does not implement it |
| `document.getElementsByClassName('x')` after the tree or class attributes change | a live `HTMLCollection` of descendants matching the class names | a snapshot. The Document and Element hooks re-run AngleSharp's class matching through `DomLiveHtmlCollection` on each read ([#3897](https://github.com/sebastienros/jint/issues/3897)) |
| `getElementsByClassName('A a')` in quirks mode | [DOM's class-name collection algorithm](https://dom.spec.whatwg.org/#concept-getelementsbyclassname) compares ASCII case-insensitively in quirks mode and identically otherwise; U+212A KELVIN SIGN stays distinct from ASCII K/k | 1.8.0 compares case-sensitively in both modes. With `<html class="a A"><body class="a a">` and no doctype, the document query returns only `html`, omitting `body`. Current upstream [class matching](https://github.com/AngleSharp/AngleSharp/blob/1b8579bea408b816891c61d047eb80152fc4f9af/src/AngleSharp/Dom/QueryExtensions.cs#L371-L385) still uses `ClassList.Contains`; the CSS class-selector path has the same defect and no comparer overload is exposed. Upstream [AngleSharp#1319](https://github.com/AngleSharp/AngleSharp/issues/1319) and [AngleSharp#1321](https://github.com/AngleSharp/AngleSharp/pull/1321) were declined as out of scope, so [#3899](https://github.com/sebastienros/jint/issues/3899) moved the ownership here: the whole algorithm is `DomHostHooks.GetElementsByClassName` now -- the ordered set of classes, the empty-set answer, and an ASCII-only fold read from the node document's `compatMode` on every read of the live collection. AngleSharp's own query is no longer on the path
| `:lang(en)` on an element with no declared or inherited language | [Selectors §8.1](https://drafts.csswg.org/selectors-4/#the-lang-pseudo) matches the element's content language; an element whose language is unknown matches no language range | 1.8.0 falls back to `IBrowsingContext.GetCulture()`, so the element matches on an English-culture context and does not on an invariant one. `ParserDriver` supplies the page engine's `Options.Culture` to make that fallback independent of the parser thread, and the browser WPT lane pins invariant culture, but neither changes AngleSharp's matching rule. An upstream report has been drafted but not filed |
| `:enabled` and `:disabled` on a link, on `<fieldset disabled>` or `<optgroup disabled>`, and inside a disabled `select` or an outer disabled `fieldset` | [HTML §4.16.3](https://html.spec.whatwg.org/multipage/semantics-other.html#selector-enabled) matches `:enabled` against the seven element types which have a disabled state and `:disabled` against every [actually disabled](https://html.spec.whatwg.org/multipage/semantics-other.html#concept-element-disabled) element. `disabled` is a boolean attribute, an `optgroup` or `option` is disabled by its nearest ancestor `select`, a `fieldset` inside a disabled fieldset is a disabled fieldset itself, and a disabled fieldset excuses only its own first `legend` | Css 1.1.0's `IsEnabled`/`IsDisabled` give a link a disabled state; read the *value* of `disabled` on an `optgroup`, `menuitem` or `fieldset`, so `<fieldset disabled>` matches `:enabled` and never `:disabled`; stop at the nearest ancestor fieldset even when that one shelters the element in a legend and an outer one does not; and know nothing of the `select` above an `optgroup` or `option`. `PagePseudoClassSelectorFactory` owns §4.15's disabled state outright, over element interfaces and attribute presence, and asks AngleSharp only for the two selectors' text and specificity. Upstream [AngleSharp#1324](https://github.com/AngleSharp/AngleSharp/issues/1324) and [AngleSharp#1326](https://github.com/AngleSharp/AngleSharp/pull/1326) covered the link half alone and were closed without merging |
| `:target` with duplicate IDs, a matching shadow-tree ID, or a disconnected element | [Selectors §8.2](https://drafts.csswg.org/selectors-4/#the-target-pseudo) matches the document's target element; HTML selects the first matching ID or legacy named anchor in the document tree, trying the raw fragment before its percent-decoded form | 1.8.0's `IsTarget` compares each candidate's ID with its owner document's location, so every duplicate, a shadow descendant, and a disconnected clone can match. `PagePseudoClassSelectorFactory` selects the one indicated element from the HTML document instead. No upstream issue has been filed |
| `:any-link` / `:link` / `:visited` on HTML and SVG hyperlinks | [Selectors §8.1](https://drafts.csswg.org/selectors-4/#the-any-link-pseudo) makes `:any-link` exactly the union of the two link-history states; HTML makes every `a[href]` and `area[href]` a hyperlink even when the attribute is empty, while SVG makes an SVG `a` with either `href` or `xlink:href` a hyperlink unless it descends from another hyperlink element | 1.8.0's common `IsLink` helper omits empty-`href` HTML anchors and every area, matches a `link[href]`, and recognizes no SVG anchor; `:any-link` reuses that helper and `:visited` matches nothing. `PagePseudoClassSelectorFactory` supplies the HTML and SVG partitions, keeps all qualifying hyperlinks unvisited, applies SVG's ancestor rule directly over the DOM parent chain, and constructs `:any-link` from those corrected states. No upstream issue has been filed |
| `document.getElementsByTagName('x')` after the tree changes | a live `HTMLCollection`, with qualified-name matching that folds ASCII only for HTML-namespace elements in an HTML document | a snapshot, and its one comparison folds names from other namespaces too. `DomLiveHtmlCollection` re-runs the filter for every read; the four Document/Element qualified-name and namespace-name operations reach it through generated hooks |
| `getElementsByTagNameNS('test', 'BODY')` | DOM's namespace/local-name collection algorithm matches both strings exactly and returns a live `HTMLCollection` | the exact-namespace query folds the requested local name, although `IElement.LocalName` retains the created case. The generated hook traverses non-HTML namespaces itself; exact HTML-namespace queries stay on AngleSharp's path because that path retains name information its `IElement` surface does not expose ([#3948](https://github.com/sebastienros/jint/issues/3948)) |
| `document.getElementById('')` and `fragment.getElementById('')` | DOM §4.9 unsets an element's ID while its `id` content attribute is absent or the empty string, so DOM §4.5's lookup can never match the empty string and answers `null` | 1.8.0 compares the attribute's value, so the empty string matches the first element whose `id` is absent -- the document element of an ordinary page, and any `<div id="">` in a fragment. Both spellings are `hooks` entries that answer `null` for the empty key before AngleSharp is asked (`DomHostHooks.GetElementById`)
| `collection.namedItem('qux')` where `qux` is the `name` of a non-HTML element | [HTML's named lookup](https://html.spec.whatwg.org/multipage/common-dom-interfaces.html#dom-htmlcollection-nameditem) is the **first** element in tree order whose ID is the key **or** which is in the HTML namespace and whose `name` content attribute is the key | `IHtmlCollection<T>`'s string indexer matches `name` on any element in any namespace, and does so in a second pass after every id -- so `document.createElementNS("", "img")` with `name="qux"` answered, and `<img name=foo><img id=foo>` answers the second where a browser answers the first. `DomHtmlCollectionObject.NamedItem` walks the collection itself, which is also what makes it agree with the supported-property-name list beside it
| `child.before('text', child)`, `child.after(x, child)`, `child.replaceWith(x, child)` | DOM §4.2.8 picks the viable previous (or next) sibling -- the nearest one that is not itself an argument -- **before** "convert nodes into a node", because that conversion moves argument nodes into a fragment; `replaceWith`'s last step then asks whether the receiver is still a child of the parent at all | 1.8.0's `IChildNode.Before`/`After`/`Replace` convert first and then insert relative to the receiver, so the reference node has already left the parent and `InsertBefore` raises `NotFoundError` -- "The object can not be found here" out of nine assertions of `ChildNode-before`/`-after`/`-replaceWith`. `Replace` also converts before it checks whether the child has a parent. All three are `DomChildNodeMembers` now; `before` and `after` are `hooks` and `replaceWith` an `additions` entry, because AngleSharp spells it `replace`
| `svgA.relList`, `mathA.relList` and `form.rel` | SVG 2 gives `SVGAElement` a `rel`/`relList` pair, and HTML §4.10.3 gives `HTMLFormElement` one | AngleSharp builds a bare `SvgElement` for an SVG `<a>` and a `MathElement` for a MathML one, declares no `[DomName("SVGAElement")]` at all, and gives `IHtmlFormElement` neither member -- so there is nothing for the generator to project and nothing a `reflected` entry could replace. Two rows of `dom/lists/DOMTokenList-coverage-for-attributes.html` stay excluded for it; answering them would mean this package declaring an SVG interface of its own, which is the one thing it is not for
| `link.href` after the document's first `<base href>` is removed | HTML's URL-reflection algorithm resolves the content attribute against the element's node document's current base URL on every read | `IHtmlLinkElement.Href` retains the removed base element's URL. The reflected-attribute descriptor now reads `PageRuntime.BaseUri` for the page's own document and derives the current first `base[href]` against the owner document's uncached URL everywhere else ([#3896](https://github.com/sebastienros/jint/issues/3896)) |
| `meta.charset` | HTML declares a `charset` content attribute but no corresponding IDL member | 1.7.3 annotates its CLR convenience property with `[DomName("charset")]`; the override table omits it while preserving normal content-attribute access |
| invalid selector failures | a catchable `SyntaxError` DOMException | the old `:has(*,:jqfake)` null dereference is fixed upstream, so the selector-only wrapper and its broad `NullReferenceException` translation were removed. Generated selectors use `DomFailures.Guard` like other DOM operations; remaining selector-matching differences stay upstream |
| an invalid selector on an empty `DocumentFragment` | selectors are parsed before matching, so `querySelector('[')` and `querySelectorAll('[')` raise `SyntaxError` even when nothing can match | 1.8.0 returns an empty result without parsing. This also occurred through the removed selector wrapper; error translation cannot supply validation the underlying call never performs |
| `el.id` when the attribute is absent | `""` | fixed in 1.7.3 along with other attribute-backed getters ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1313)). `DomConvert.Text` remains the non-nullable `DOMString` conversion, not a workaround specific to `id`; nullable DOM returns still take `NullableText` |
| `insertAdjacentHTML`'s position | a WebIDL enumeration | 1.7.3 adds `[DomLiterals]` to `AdjacentPosition` ([upstream change](https://github.com/AngleSharp/AngleSharp/pull/1311)). Its generated conversion is unchanged; the general lower-case-field heuristic still serves other enums without that attribute |
| `matchMedia(q).matches` | evaluates the query against the viewport and media preferences | Css 1.1.0 replaces the native stub and fixes list OR, media-type guards, orientation/scan constants and scripting. `PageRenderDevice.IRenderDevicePreferences` now lets native stylesheet rules read the page's defaults and emulated preferences. `Runtime/MediaQuery` remains: the release still distributes `not` across conjunction terms, mishandles boolean dimensions and colour availability, throws on malformed query text, and lacks ordered gamut/dynamic-range validators. The page also owns preference-change notification and scheduling |
| `style.setAttribute('media', '5%')` | HTML §4.2.6 makes `<style>`'s `media` a plain reflected `DOMString`, and DOM §4.9 gives `setAttribute` no failure mode for an already-valid attribute name; [Media Queries §2.1](https://drafts.csswg.org/mediaqueries-4/#error-handling) requires a media query that does not match the grammar to be *replaced by* `not all` rather than refused | AngleSharp core registers an `IAttributeObserver` for `media` on `HtmlStyleElement` (and `SvgStyleElement`) that assigns the sheet's `MediaList.MediaText`, and AngleSharp.Css implements that setter as `SetMediaText(value, throwOnError: true)`, which raises `DomException(DomError.Syntax)` for a query list it cannot parse. So writing an unparseable `media` on an inserted `<style>` throws out of `Element.setAttribute` itself — and out of the reflected `media` setter with it, since that setter *is* one `setAttribute`. `<link>` registers the same observer and does not throw only because its sheet is null until the resource loads. Nothing here can move it without swallowing a `DOMException` the binding exists to surface; sixteen `reflection-metadata.html` rows name the exact values, and the other thirty tests of the member pass. No upstream issue has been filed |
| `meter.value = 1e-10` | HTML §2.6.1 writes "the best representation of the number as a floating-point number", which is ECMAScript's Number-to-String: `1e-10`, and `0` for negative zero | `HtmlMeterElement`'s six setters write `Double.ToString(NumberFormatInfo.InvariantInfo)`, which spells the exponent `1E-10` and keeps `-0`. The **getters** are right and are not reflection — AngleSharp implements §4.10.14's clamping and defaults, `max` answering 1 when the attribute is absent and `optimum` the midpoint — so there is no `reflected` row for them and eighteen `reflection-forms.html` rows name the three values per member that differ. No upstream issue has been filed |
| `document.body` under a document element that is not an `html` element | [HTML §3.1.3](https://html.spec.whatwg.org/multipage/dom.html#the-body-element): the body element is the first `body` or `frameset` **child of the document's html element**, and the html element is the document element only when that element is itself an HTML-namespace `html`; the standard's own example is a `body` inserted beneath an SVG document element, where the getter still answers null | 1.8.0's getter walks `DocumentElement.ChildNodes` for the first `HtmlBodyElement` or `HtmlFrameSetElement` and never asks what the document element is, so an XML document rooted at an XHTML `div` answers its nested `body` — and so does one rooted at an `html` from another namespace ([#3976](https://github.com/sebastienros/jint/issues/3976)). The getter is a `hooks` entry (`DomHostHooks.Body`) that answers `null` before AngleSharp is asked; past that gate the child search is still AngleSharp's, because that half already matches — it takes the first `body`-or-`frameset` child and looks no deeper. Neither has been filed upstream |

| `<img srcset="a.png 1x, b.png 2x">`, and a `<picture>` with `<source media>` | [HTML §4.8.4.3.6](https://html.spec.whatwg.org/multipage/images.html#selecting-an-image-source) selects a candidate from the descriptors, the `sizes` attribute and each `<source>`'s `media` and `type` | `SourceSet.GetCandidates` ignores every descriptor and yields the candidates in order, so the **first** is always chosen; `SourceSet.ParseDescriptor` is unreachable from it and `GetWidthFromLength` answers a constant 0; `ElementExtensions.GetImageCandidate` never evaluates `media` at all and tests `type` only against the registered image services. The row stays because the AngleSharp behaviour is unchanged and `HtmlImageElement.ActualSource` still answers from it |
| `<template><img src="…"></template>` | DOM §4.2.3: a template's contents belong to a separate **template contents owner** document, which is not fully active, so [*update the image data*](https://html.spec.whatwg.org/multipage/images.html#update-the-image-data) step 2 stops before any fetch and template markup opens no socket | `HtmlTemplateElement` builds its content fragment over the *same* document, so the image inside it has a fully active node document and is fetched like any other — a page's template markup reaches the network and fires `error` or `load` at an element no browser would have loaded.
