# Host-object shapes: projecting host state into script

> **Read this when:** You are projecting host state into script — a fixed record, a prototype, a live indexed
> collection, a named record or a callable — rather than assembling the property model out of
> `ObjectInstance`'s virtuals by hand.
>
> This is the recipe half of a trap stated in [`AGENTS.md`](AGENTS.md#host-contract-verification) beside it,
> which carries the subclassing cliff, `PropertyAccessSemantics`, the pinned probe counts, the two
> probe-lowering levers these shapes build on, and the host-contract verification every hook below is checked
> by. Read that first — nothing here is repeated there, and the repository-root
> [`AGENTS.md`](../../../AGENTS.md) carries the build and test commands and the branch to target.

### Which shape fits which data

- Where the data is a fixed record, do not subclass at all: `JsObject.Create(engine, layout, values)` and `JsObject.CreateFromEntries` build straight into the hidden-class representation, so objects sharing a layout share one shape and a script reading a batch of them keeps a monomorphic inline cache. `Engine.Advanced.HasSharedShape` lets a test prove the shaping actually happened, since both fall back to the dictionary representation silently; it is a contract, so a host may commit that assertion to its own suite (`GetObjectRepresentation` is the non-contract diagnostic to reach for when a `false` needs explaining).
- Where the object is a **prototype** rather than a record, do not subclass either: `JsObjectShape` declares the members once per process and `Instantiate` creates one such object per engine, in the same shared-layout representation the engine's own intrinsics use. Members materialize per member on first access in that engine, and two properties follow from the representation rather than from anything the host declares — existence and enumerability questions are answered from the layout without creating the member's function (the one exception is the factory form of `PerRealmSlot`, whose flags are not knowable until its factory has run, so it defers), and the object is a valid *holder* for the prototype-method inline cache, which an `ObjectInstance` subclass used as a prototype can never be (see [when you add a fast lane](AGENTS.md#when-you-add-a-fast-lane-decide-who-can-reach-it)). None of this changes the probe counts in [`AGENTS.md`](AGENTS.md#host-contract-verification): those are about the receiver, and a host instance in front of a shaped prototype still pays exactly what its own semantics cost it. Because `Instantiate` returns a type the host cannot derive from, per-prototype bookkeeping goes on the object through `JsObjectShape.SetHostState` / `GetHostState` rather than in a field — an `object?` the engine never reads. It is per *instance*, not per shape, so unlike the delegates and constants inside a shape it **may** be engine-affine, and it dies with the object; a member implementation reaches it by walking up from its receiver, and `GetHostState` answers `null` for a `null` argument so that walk is one expression. Attaching it after creation rather than at `Instantiate` is what lets it hold a reference to the constructor whose `prototype` *is* that object.
- Where the data is a **live indexed collection** (a DOM `NodeList`, a result window, any lazily computed list), derive from `ArrayLikeObject` instead of assembling the property model by hand. A subclass supplies only `uint Length` and `bool TryGetIndex(uint, out JsValue)`; the base class derives the whole coherence matrix from them — the two hooks above, `GetOwnProperty`, both key enumerations, and WebIDL-shaped `Delete`/`DefineOwnProperty` refusals — and two engine lanes key on the *type*: `ArrayOperations` (so `Array.prototype` generics, the array iterator behind `for-of`/spread/`Array.from`/destructuring, and `apply`-spreading cost **one** `TryGetIndex` per element with no key object) and the interpreter's computed-read branch (so `list[i]` costs one `TryGetIndex` with no `Reference` and no descriptor). It is deliberately array-*like*: `Array.isArray` stays `false`, exactly as a browser answers for a `NodeList`. Its elements are deliberately read-only, and **every member it derives is sealed** — `Get`, `GetOwnProperty`, `GetOwnPropertyKeys`, the probe, `Set`, `Delete`, `DefineOwnProperty` — so a host needing to intercept every named read stays on plain `ObjectInstance`, and a host wanting a *named member* declares one through the named-projection hooks below rather than by overriding three of those and keeping them consistent by hand. It is a host subclass like any other, so it is a receiver the caches may serve and never a holder they may trust — a `NodeList.prototype` carrying the collection's methods wants `JsObjectShape` above. A third, optional `protected virtual bool HasIndex(uint)` answers the existence-only questions (`in`, `hasOwnProperty`, the key enumerations, `delete`, the generics' per-element hole test) without projecting an element to discard; its default is exactly `TryGetIndex`-and-discard, so overriding it is pure opt-in, and it carries the same agree-with-`TryGetIndex`-at-the-same-instant obligation the other hooks carry, verified on every probe whenever host-contract verification is on. **`length` is the fourth hook.** `OwnsLength => false` puts it on the prototype; `PristineLengthGetter` names that prototype's original accessor, so a read answers from `Length` under the cache's guards; an own `length`, a moved prototype or a redefined accessor wins on the next read.
- Where the data is a **named record** projected from native state — a settings bag, a row, a document, a live view over a host struct — derive from `NamedPropertyObject`, the sibling of `ArrayLikeObject` for the string-keyed case. It exists because that host used to write **five to eight** mutually-consistent hooks by hand (`GetOwnProperty`, `ProbeOwnProperty`, `GetOwnPropertyKeys`, `TryGetOwnPropertyValue`, `Set`, `Delete`, `DefineOwnProperty`). A subclass now supplies `int NameCount`, `string NameAt(int)` and `bool TryGetNamedValue(string, out JsValue)`, and the base class **seals** all seven of those plus `Get` and `HasProperty`. Because the base overrides `TryGetOwnPropertyValue`, a host reaches the zero-descriptor column of the probe counts in [`AGENTS.md`](AGENTS.md#host-contract-verification) **without knowing it exists**: every read row costs no descriptor and no probe. Symbols and names the projection does not carry stay entirely ordinary, so `Symbol.toStringTag`, `Symbol.iterator` and expandos work as they always did. Sealing `Get` is what makes the `Ordinary` claim its constructor makes true by construction: a host needing to observe reads that resolve on its *prototype* stays on plain `ObjectInstance` — every *own* read is already `TryGetNamedValue`.

### The named-projection hooks

- **The named-projection hooks are one set, and both classes publish the same one.** `NamedPropertyObject` declares the first three `abstract`, because a record with no names is not a record; `ArrayLikeObject` declares all eight `virtual` with empty defaults, because a collection with no named members is the common case — and it derives from the runtime type once, cached per `Type` the way `PropertyAccessSemantics` is, whether the type declared any of them at all, so a collection that declared none is never asked. One shared implementation (`NamedProjection.cs`, reached through the internal `INamedProjection` both classes implement explicitly) derives the model from them for both, because two hand-kept copies would reproduce *inside the engine* exactly the incoherence these classes exist to spare a host.

  | hook | default | decides |
  | --- | --- | --- |
  | `NameCount` / `NameAt(int)` | `0` / throws | which names exist, and the enumeration order script sees |
  | `TryGetNamedValue(string, out JsValue)` | carries nothing | the value; `false` is an **authoritative** own miss |
  | `HasName(string)` | ask and discard | existence, with no value produced |
  | `IsNameEnumerable(string)` | `true` | the `enumerable` attribute |
  | `IsNameWritable(string)` | `false` | the `writable` attribute **and** whether assignment routes to the host |
  | `TrySetNamedValue(string, JsValue)` | refuses | one `[[Set]]`; `false` is a refusal, so strict `TypeError` / sloppy no-op |
  | `TryDeleteName(string)` | refuses | one `[[Delete]]`; `false` is a refusal, so `delete` is `false` / strict `TypeError` |

  Three things the defaults buy: a projection that overrides none of the last three is exactly the read-only object the first version of these classes was, so nothing that compiled against it changes; writability is declared **per name** rather than per object, which is what keeps a record with computed fields beside writable ones honest; and `configurable: true` is not a hook at all, because the `[[GetOwnProperty]]` invariants forbid anything else for a projection that may lose a name. That is also why `Object.defineProperty` on a projected name stays refused whatever `IsNameWritable` says — the projection owns all three attributes, so assignment is the write path and a redefinition has nothing to change. `IsNameWritable` answering `true` for a name the projection does *not* yet carry is the WebIDL named-property-setter shape and lets an assignment **create** the name; it runs ahead of the prototype chain and only when the receiver is the object itself. On `ArrayLikeObject` the projection is the *named* half only: canonical array indices and `length` are answered from `Length`/`TryGetIndex` first and a projected name may not spell one.

### Where the host member is a callable

- **Where the host member is a *callable*, derive from `HostFunction`** (`Jint/Native/HostFunction.cs`) — the function sibling of the two classes above, and the same shape: one abstract member (`Invoke`), everything derived from it sealed. It exists because `Function` *looked* derivable and was not: its only accessible constructor took a `Realm`, and no public member returns one, so `Function.Call` was a `protected abstract` extension point nobody outside the assembly could reach. `Call` is sealed here on purpose, so that what surrounds the body — today, routing an escaping CLR exception through `Options.Interop.ExceptionHandler` exactly as `ClrFunction` does — is a property of the class rather than something each subclass reproduces; both classes share that routing through the `private protected` `Function.ClrExceptionsBubble` / `TranslateClrException` pair, so a new host-callable shape must reach for those rather than growing a third copy. It installs `name` and `length` with the attributes [§10.3](https://tc39.es/ecma262/#sec-built-in-function-objects) gives a built-in (`{ writable: false, enumerable: false, configurable: true }`), which is a deliberate deviation from `ClrFunction`'s non-configurable `length` default — that one is compatibility, this one is new. A host wanting `new` derives from `Constructor` instead; both host-facing constructors take the *principal* realm's `Function.prototype`, never the running realm's, so a callable built after a `ShadowRealm` exists is still a `Function` the surrounding script can recognize.
