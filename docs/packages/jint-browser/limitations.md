# Limitations

`Jint.Browser` is not a rendering engine.

- No pixels, screenshots, PDF output, browser window, canvas rendering, WebGL, or media playback.
- No visual layout. Synthetic boxes are deterministic tree rows; text does not wrap and elements are never truly side by side.
- Geometry, hit testing, scrolling, intersection, and resize observations use that synthetic model.
- Web Animations effects never change computed style or layout, and style sheets create no `CSSAnimation` or `CSSTransition` objects. `commitStyles()` explicitly writes discrete keyframe values (the last specified value at or before iteration progress), without interpolation, additive composition, or an effect-stack cascade. Connected HTML/SVG elements are treated as rendered; pseudo-element effects cannot commit styles. Frames use a fixed 16 ms cadence, shared with `requestAnimationFrame`; paused, idle, zero-rate and finished animations do not keep a frame timer alive. Only document timelines are supported. Keyframe property names use the native CSS catalog; property values retain the parser's text-only CSS boundary rather than per-property grammar validation.
- Images are fetched and their container headers read, never their pixels. `complete`, `currentSrc`, `naturalWidth`/`naturalHeight`, `width`/`height` and the `load`/`error` events answer per HTML §4.8.4; PNG, JPEG, GIF, WebP, BMP, ICO and SVG state a size, and any other container is the *broken* state with an `error` event. `srcset`, `sizes` and a `<picture>`'s `<source media>`/`type` select a candidate per HTML §4.8.4.3.6, against the configured viewport and device scale factor, and `img.decode()` resolves once the current request is completely available and rejects with an `EncodingError` when it is broken. There is no bitmap, no colour, no EXIF orientation and no animation, so an animated GIF is its logical screen and has no frames. `loading="lazy"` loads eagerly: whether an image intersects the viewport is a question about a layout this package does not have. Set `BrowserOptions.MaxImageRequests` to `0` to fetch none, which records every reference in the request log as before.
- Fonts are fetched and their file signature checked, never decoded, so nothing about a face's glyphs or metrics is known. A `local()` source is never available, `@font-face` rules do not add faces to `document.fonts`, and a set matches faces by family name and `unicode-range` only. `document.fonts.ready` waits for the faces in the set, not for the document to finish loading, and workers have no `fonts`.
- Child-frame documents can be fetched and parsed, but do not have a script realm. `contentWindow` is `null`.
- No IndexedDB, Cache Storage integration for page origins, WebAssembly, CSP enforcement, SharedWorker, or ServiceWorker.
- Cookie Store has no service-worker `CookieStoreManager` or subscriptions. Following the current [Cookie Store IDL](https://cookiestore.spec.whatwg.org/#dictdef-cookielistitem), results contain only `name` and `value`, not Chrome's additional attributes; deleted event items omit `value`. `sameSite` is validated and `partitioned` converted, but the default `CookieContainer` jar retains neither and does not enforce them. Its existing capacity, grammar and domain restrictions still apply (including refusal of empty names), and there is no public suffix list. Custom non-`CookieContainer` jars expose neither HttpOnly nor cookie identity/attributes: as with `document.cookie`, those jars must themselves hide/protect HttpOnly cookies; attributes must be representable by a Set-Cookie string.
- Cookie Store change detection snapshots script-visible cookies only while a `change` listener or `onchange` handler is registered. Processing occurs after page turns, in nested rendering pumps and on idle wakes for external writes/expiry; each interval's net changes produce one later task. Intermediate writes/deletions, unchanged-value rewrites and attribute-only changes the jar cannot retain are not reported. No jar scans, timers or CookieStore allocation occur for an unused API. Jar operations run synchronously on the page loop, with results and parallel-algorithm validation failures settled in queued tasks; WebIDL conversion and early origin/URL checks reject immediately.
- Like the other `[SecureContext]` APIs, Cookie Store is exposed without secure-context gating. Opaque origins and non-HTTP(S) creation URLs (including inherited `about:blank`) reject with `SecurityError`. Writes always use Secure cookies, so non-loopback HTTP writes are ignored by the storage model; HTTP loopback is trusted for Secure cookie retrieval by the default shared jar.
- No drag and drop, clipboard API, touch event dispatch, or native input.
- Nothing is ever granted: every `navigator.permissions.query` answers `prompt` and `Notification.permission` is `default`, so a `Notification` fires `error` rather than showing. `registerProtocolHandler` validates its arguments and registers nothing, `screen.orientation.lock` rejects with `NotSupportedError`, and `navigator.storage` reports a 1 GiB quota with no usage and never persists. `navigator.userAgentData` names Jint.Browser only while the user agent is its own; any other user agent without metadata has no brands, and no `Sec-CH-UA` request headers are sent.
- No file picker: clicking an `<input type=file>` records that a page asked for one. `Page.SetInputFilesAsync` and `DOM.setFileInputFiles` make the selection instead.
- Hover dispatches movement but not mouse boundary events such as `mouseenter`.
- `contenteditable` support is intentionally limited; structural editing such as Enter-created blocks is absent.
- Isolated CDP worlds are aliases, not isolated realms.
- Playwright and Puppeteer compatibility covers supported public/client paths, not every browser or protocol feature.
- The package is not currently trim- or AOT-compatible.

Some CSS values come from AngleSharp's declared cascade rather than a computed layout. Stylesheet `@media` rules read the same emulated viewport, media type, and supported preferences as `matchMedia`, through AngleSharp.Css 1.1.0. Their evaluators still differ for negated conjunctions, boolean dimensions and colour features, malformed queries, and ordered gamut/dynamic-range preferences; see the [DOM divergence register](https://github.com/sebastienros/jint/blob/main/Jint.Browser/Dom/divergences.md).

Prefer feature detection and handle `NotSupportedException` or protocol errors. Never use synthetic geometry as evidence of real visual placement.
